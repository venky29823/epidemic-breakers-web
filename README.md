# Epidemic Breakers — Interactive Web Demo

Live: <https://venky29823.github.io/epidemic-breakers-web/> (GitHub Pages, HTTPS)

Interactive demo for the **Epidemic Breakers** OptiForge 2026 project
(Track 05: Intelligent Systems & Autonomous Computing).
Main study repo: <https://github.com/venky29823/epidemic-breakers-optiforge26>

Tune per-edge circuit-breaker thresholds on a 40-node / 111-edge microservice
call graph and watch failure cascades unfold: a call-graph canvas with a time
scrubber, an epidemic curve, a theta-vs-noise plot, an honest
mean ± sd strategy comparison, Round 1 / Round 2 environment presets, a
small-budget in-browser GA, and shareable URL state.

## Zero-dependency static site

HTML + CSS + vanilla JS only. No npm packages, no bundler, no CDN scripts.
The cascade simulator, fitness function, edge-betweenness computation, and a
mini genetic algorithm are ported to JavaScript in `sim.js`; the UI lives in
`app.js`. `node --test` is allowed for tests only.

## Run locally

```bash
python3 -m http.server 8000   # from this directory
# open http://localhost:8000
```

The page must be served over HTTP (the data files load via `fetch`); opening
`index.html` directly from disk will not work.

## Parity tests

```bash
node --test        # runs tests/parity.test.js (14 tests, <1s)
node --check sim.js
node --check app.js
```

`tests/parity.test.js` checks the JS port against
`data/reference_results.json`, which was generated by the **Python**
simulator (`src/simulator.py::_run`) and networkx on the exact data files
this site ships. Deterministic parts match exactly (graph edges, per-edge
params, edge betweenness up to normalization, theta length, the F formula);
mean F for fixed-0.5, GA and oracle is compared over 256 scenarios with an
explicit ±2.0 tolerance (deltas observed: −0.76, −0.54, +0.55).

Regenerate the reference (from the web repo root; needs the Python study repo):

```bash
python3 /tmp/gen_reference.py   # generator kept with the study notes
```

## Python parity — known differences

- **RNG**: Python uses NumPy PCG64; JS uses cyrb53-seeded mulberry32.
  Scenario-by-scenario equality is *not* expected and is never claimed.
- **Draw pattern**: Python draws full n×n random matrices per step; JS draws
  per-edge. Per-edge marginals are identical, so mean F agrees statistically.
- **Betweenness normalization**: networkx returns ÷ n(n−1); the JS Brandes
  is unnormalized. Only ratios matter downstream (guidedWeights
  sum-normalizes); parity tests compare ratios to ~1e-9.
- **Non-default environments**: moving the spread/noise sliders regenerates
  per-edge params with a JS-side hash that differs from Python's
  `_per_edge_params`. Only the baked-in default environment is
  cross-language identical.
- **Oracle**: `theta_e = min(1, noise_e + 0.10)` (JS) ≡
  `clip(noise_amp_e + 0.10, 0, 1)` (Python) for the shipped non-negative
  noise values. The +0.10 margin is an arbitrary heuristic choice, not a
  derived optimum.

## File map

| Path | What |
|---|---|
| `index.html` | Page structure, controls, limitations footer |
| `app.js` | UI logic: runs, canvases, comparison, GA, URL state |
| `sim.js` | Dependency-free sim/GA core (browser + node) |
| `styles.css` | All styling, responsive down to 360px |
| `data/graph.json` | 40 nodes, 111 edges (from the study) |
| `data/edge_params.json` | Per-edge noise/spread for the default env |
| `data/best_theta.json` | GA-optimized threshold vector (train seeds) |
| `data/reference_results.json` | Python-generated reference for parity tests |
| `tests/parity.test.js` | `node --test` parity suite |
| `.github/workflows/test.yml` | CI: runs `node --test` on push/PR |

The `data/` files were exported from the main study repo (graph from
`graph_gen`, params from `simulator._per_edge_params`, `best_theta.npy`);
never hand-edit them. The main repo's `scripts/check_web_parity.py`
independently verifies the baked-in data against the Python source of truth.

## Limitations (also shown on the page)

- The JS simulator is a port of the Python original with a different RNG —
  results are distributionally comparable, not identical.
- Strategy comparisons use small samples (8/20/50 scenarios); differences
  smaller than the spread are not meaningful.
- The oracle is a noise-following heuristic, not a proven optimum.
- Thresholds are graph-specific and do not generalize to other topologies.
